## 1. Установка Android Studio

**Шаги:**

1. Открыть https://developer.android.com/studio.
2. Скачать сборку под свою ОС:
   - Windows — `.exe` установщик;
   - macOS — `.dmg` (отдельные сборки для Intel и Apple Silicon);
   - Linux — `.tar.gz`, распаковать в `/opt/android-studio`.
3. Запустить установщик, оставить настройки по умолчанию.
4. При первом запуске мастер (`Setup Wizard`) предложит скачать SDK и Emulator — **согласиться** (объём около 3-4 ГБ).
5. Дождаться завершения установки SDK.

**На что обратить внимание:**
- Убедиться, что установлены пакеты **Android SDK Platform-Tools** и **Android Emulator** (Tools → SDK Manager).
- На macOS с Apple Silicon (M1/M2/M3) выбирать образы `arm64-v8a` — иначе эмулятор будет тормозить.
- На Windows включить **Hyper-V / WHPX** (или Intel HAXM для старых процессоров) в разделе «Компоненты Windows», иначе эмулятор не запустится.

📸 `screenshots/android_01_studio_installed.png` — стартовое окно Android Studio с только что установленным SDK.

## 2. Создание эмулятора с Play Market

**Шаги:**

1. В стартовом окне Android Studio → **More Actions → Virtual Device Manager** (или Tools → Device Manager, если открыт проект).
2. Нажать **+ Create Device**.
3. **Category: Phone**. Выбрать модель — например, `Pixel 7` (полностью поддерживает Play Market).
4. **Важно:** в столбце **Play Store** должен стоять значок магазина ▶️. Устройства без него (`Nexus`, `Pixel 4` без Google APIs) не подойдут — Play Market не запустится.
5. Нажать **Next**.
6. Выбрать образ системы — например, `Android 14.0 (UpsideDownCake), API 34, Google Play` (именно `Google Play`, не `Google APIs`).
7. Нажать **Next**, оставить конфигурацию по умолчанию, дать имя эмулятору (`Pixel_7_API_34_PlayStore`).
8. **Finish**.
9. В Device Manager нажать ▶ рядом с созданным устройством. Эмулятор запустится за 30-90 секунд.
10. Дождаться загрузки главного экрана, свайпнуть вверх → найти иконку **Play Store**, войти в свой Google-аккаунт (только для теста — не основной).

**На что обратить внимание:**
- Play Market работает **только на образах "Google Play"**, а не "Google APIs" — это самая частая ошибка новичков.
- На macOS ARM выбирать образы, помеченные как `arm64-v8a` — они запустятся моментально в отличие от x86_64.
- Первый запуск может занять 2-3 минуты — это нормально.

## 3. Режим разработчика

Скриншот делается либо с физического устройства, либо с эмулятора.

**Шаги (общие для Android 8+):**

1. Открыть **Settings → About phone** (или **Settings → System → About emulated device** для эмулятора).
2. Найти строку **Build number** — тапнуть по ней **7 раз** подряд.
3. После 5-го тапа появится подсказка «You are now X steps away from being a developer».
4. После 7-го тапа появится сообщение «**You are now a developer!**».
5. Вернуться в **Settings → System → Developer options** — раздел теперь доступен.
6. Внутри включить главный тумблер **Use developer options**.
7. Полезные опции, которые обычно включает QA:
   - **USB debugging** — для `adb` с физическим устройством;
   - **Stay awake** — экран не гаснет при зарядке (удобно для длительных тестов);
   - **Show taps** — визуализация касаний (для скринкастов);
   - **Pointer location** — координаты и траектория тапов;
   - **Don't keep activities** — жёсткая проверка, что приложение переживает уничтожение Activity;
   - **Background process limit → No background processes** — проверка поведения при агрессивном kill'е.

📸 `screenshots/android_03_developer_mode.png` — раздел «For developers» с включённым режимом.

## 4. Logcat в Android Studio

**Что это:** встроенный просмотрщик логов Android — показывает поток сообщений от системы, всех приложений и, отдельно, от подключённого/эмулированного устройства.

**Шаги для снятия логов:**

1. Запустить эмулятор из задания 2 (или подключить физический телефон по USB c включённым USB debugging).
2. В Android Studio открыть окно **Logcat** (нижняя панель или `Alt+6` на Windows/Linux, `⌘6` на macOS).
3. В верхнем выпадающем списке выбрать нужное устройство и процесс:
   - **Device:** `Pixel_7_API_34_PlayStore [emulator-5554]`;
   - **Process:** `com.example.myapp` (если приложение установлено), либо `No filters` для всей системы.
4. Уровень логов — выпадающий список **Verbose / Debug / Info / Warn / Error / Assert**. Для быстрого поиска ошибок обычно ставится **Warn** или **Error**.
5. Поле поиска сверху принимает Logcat query syntax:
   - `tag:MyApp` — только по определённому тегу;
   - `level:error` — только errors;
   - `package:mine` — логи только «моих» приложений;
   - `message:crash` — по подстроке в тексте лога.
6. Пример полезной комбинации: `package:com.example.myapp level:error` — фильтрует поток ровно до ошибок нашего приложения.
7. Внутри приложения совершить действие, которое хочется задиагностировать (например, нажать кнопку, вызывающую краш).
8. В Logcat увидим строки уровня `E`, `W`, `I` с временными метками и тегами.
9. Правый клик по интересной строке → **Save as** → сохранить .txt для приложения к баг-репорту.

Пример строки Logcat:
```
2026-05-10 13:42:11.234 E/AndroidRuntime(28451): FATAL EXCEPTION: main
2026-05-10 13:42:11.234 E/AndroidRuntime(28451): Process: com.example.myapp, PID: 28451
2026-05-10 13:42:11.234 E/AndroidRuntime(28451): java.lang.NullPointerException: Attempt to invoke virtual method 'java.lang.String com.example.myapp.User.getName()' on a null object reference
2026-05-10 13:42:11.234 E/AndroidRuntime(28451):    at com.example.myapp.MainActivity.onCreate(MainActivity.java:42)
```

## 5. Пошаговая инструкция «для коллеги»: создание симулятора в Xcode

*Инструкция для инженера, который никогда этого не делал.*

### Шаг 0. Предусловия

- **macOS.** Xcode работает только на Mac (это ключевое ограничение относительно Android Studio). Ни на Windows, ни на Linux запустить нельзя.
- **Свободное место на диске.** Xcode весит ~10 ГБ, плюс каждый образ iOS-симулятора — ещё 6-8 ГБ. Итого: держи как минимум 30-40 ГБ свободного места.
- **Apple ID.** Нужен для App Store, откуда ставится Xcode.

### Шаг 1. Установка Xcode

1. Открой **App Store** на Mac.
2. В поиске введи **Xcode** → нажми **Install**.
3. Установка займёт 40-60 минут (это самая долгая часть — Apple не сжимает бинарники сильно).
4. После установки запусти Xcode, прими лицензионное соглашение, введи пароль администратора для установки Command Line Tools.

**Важно:** если раньше устанавливал Command Line Tools через `xcode-select --install`, они конфликтуют с полной установкой Xcode. Проверь путь командой `xcode-select -p` — должно быть `/Applications/Xcode.app/Contents/Developer`. Если нет — исправь: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.

### Шаг 2. Открой Xcode → Settings

1. В верхнем меню: **Xcode → Settings** (или `⌘,`).
2. Перейди на вкладку **Platforms** (в старых версиях — **Components**).

### Шаг 3. Скачай симуляторы нужных iOS-версий

1. На вкладке **Platforms** увидишь список версий iOS.
2. Нажми **+ (Get platform)** → выбери нужную версию:
   - **Обязательно** — последняя iOS (iOS 18 на момент написания).
   - **Желательно** — самая старая поддерживаемая (iOS 16 или 15) для покрытия пользователей.
3. Каждая версия — 6-8 ГБ, скачивание займёт 15-30 минут.

**Важно:** iOS 17.5 симулятор запустится **только** на Xcode 15.4+; iOS 18 — на Xcode 16+. Если работаешь на Xcode 14, скачать iOS 18 симулятор нельзя — нужно обновлять Xcode или заводить второй.

### Шаг 4. Создай новую конфигурацию симулятора

1. **Xcode → Window → Devices and Simulators** (`⇧⌘2`).
2. Перейди на вкладку **Simulators** (слева).
3. Нажми **+** внизу слева.
4. Заполни поля:
   - **Simulator Name** — понятное имя, например `iPhone 15 Pro — iOS 18 QA`;
   - **Device Type** — модель устройства (iPhone 15 Pro / iPhone SE / iPad Air и т.п.);
   - **OS Version** — одна из установленных на шаге 3.
5. **Create**.

**На что обратить внимание при выборе модели:**
- Для покрытия «маленьких экранов» обязательно возьми **iPhone SE (3rd gen)** — маленький 4.7″ экран часто ломает вёрстку.
- Для покрытия «Dynamic Island» возьми **iPhone 14 Pro / 15 Pro / 15 Pro Max** — там другая безопасная зона.
- Для тестирования iPad-версии добавь **iPad Pro 11″** и **iPad mini** (маленький планшет).

### Шаг 5. Запуск симулятора

1. Двойной клик по симулятору в списке — он откроется как отдельное окно.
2. Первый запуск — 30-60 секунд.
3. По умолчанию видишь пустой домашний экран iOS.

### Шаг 6. Полезные операции для тестировщика

- **Rotate:** `⌘→` / `⌘←` (поворот экрана).
- **Home button:** `⇧⌘H` (аналог кнопки Home).
- **App switcher:** `⇧⌘H` дважды.
- **Screenshot:** `⌘S` (сохранится на рабочий стол).
- **Screen Recording:** File → Save Screen Recording (`⌘R`).
- **Смена локали и языка:** Settings → General → Language & Region — тестировщик обязан прогнать интерфейс на нескольких языках.
- **Симулировать локацию:** в меню симулятора → Features → Location → выбрать «Freeway Drive» или «Custom Location…» с указанием широты/долготы. Пригодится для геолокационных фич.
- **Push-нотификация:** Features → Trigger iCloud Sync + возможность утащить `.apns`-файл прямо на окно симулятора для отправки локальных push.

### Шаг 7. Установка приложения в симулятор

1. Из Xcode: **Product → Run** (`⌘R`) — если у тебя открыт проект.
2. Из готового .app: перетащи `.app`-бандл прямо на окно симулятора.
3. Из терминала: `xcrun simctl install booted MyApp.app`.

**Внимание:** в симулятор нельзя установить `.ipa` (это подписанная сборка для реального устройства). Только `.app`.

### Шаг 8. Общий совет: не путать симулятор и эмулятор

- **Симулятор iOS** — эмулирует **поведение** iOS, но не самого железа. Крутится на архитектуре Mac (x86 или ARM). Быстрый, но **не 100% воспроизводит реальное устройство** — часть вещей (акселерометр, камера, ARKit, полноценный Bluetooth) не работает.
- **Эмулятор Android** — полноценно эмулирует железо ARM. Ближе к реальности, зато медленнее.
- **Вывод:** для критичных финальных проверок iOS-приложения **используй реальное устройство**, не только симулятор.
