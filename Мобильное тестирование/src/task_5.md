## 1. Установка Charles Proxy и настройка окружения

### Шаг 1.1. Установка на ПК

1. Скачать с https://www.charlesproxy.com/download/ (Windows / macOS / Linux).
2. Установить. Первый запуск — 30-дневная триал-версия (для учебной задачи достаточно; для регулярной работы — лицензия $50 индивидуально).
3. Разрешить Charles автоматически стать системным прокси (Proxy → macOS Proxy / Windows Proxy).

### Шаг 1.2. Установка root-сертификата на ПК

Без этого весь HTTPS-трафик будет виден только как `CONNECT tunnel`, а тела запросов расшифровать не получится.

1. **Help → SSL Proxying → Install Charles Root Certificate**.
2. На macOS: Keychain Access → Trust → **Always Trust** для сертификата `Charles Proxy CA`.
3. На Windows: certificate → Install → Local Machine → Trusted Root Certification Authorities.

### Шаг 1.3. Настройка прокси на телефоне

Телефон и ПК должны быть в одной Wi-Fi-сети.

1. На ПК: **Help → Local IP Address** — запомнить IP (например, `192.168.1.15`).
2. Убедиться, что Charles слушает на порту **8888** (Proxy → Proxy Settings → Port).
3. На телефоне: **Settings → Wi-Fi → (i) рядом с сетью → HTTP Proxy → Manual**.
   - Server: `192.168.1.15`
   - Port: `8888`
4. При первом подключении на ПК появится диалог **Allow?** — принять.

### Шаг 1.4. Установка сертификата Charles на телефон

**iOS:**
1. В Safari перейти на **https://chls.pro/ssl** — скачается конфигурационный профиль.
2. **Settings → General → VPN & Device Management → Charles Proxy CA** → **Install**.
3. **Settings → General → About → Certificate Trust Settings** → включить полное доверие для Charles.

**Android:**
1. В браузере устройства открыть **https://chls.pro/ssl** — скачается `.pem`.
2. **Settings → Security → Install certificate** → выбрать файл.

**Важно для Android 7+:** приложения по умолчанию не доверяют пользовательским сертификатам. Для отладки собственного приложения разработчик должен добавить в `network_security_config.xml`:
```xml
<network-security-config>
    <debug-overrides>
        <trust-anchors>
            <certificates src="user"/>
        </trust-anchors>
    </debug-overrides>
</network-security-config>
```
Без этого HTTPS-трафик приложения расшифровать нельзя. Для веб-приложений в браузере устройства это не требуется — браузер уважает пользовательские сертификаты.

### Шаг 1.5. Включение SSL Proxying

Чтобы Charles расшифровывал HTTPS-трафик конкретных доменов:

1. **Proxy → SSL Proxying Settings → SSL Proxying** → включить чекбокс **Enable SSL Proxying**.
2. Добавить хосты:
   - `*.ozon.ru:443`
   - `api.ozon.ru:443`
   - `*.oz-cdn.ru:443`

📸 `screenshots/charles_01_setup.png`

## 2. Ключевые функциональности Charles Proxy

| Функция | Назначение | Практические задачи тестировщика |
|---------|-----------|----------------------------------|
| **Фильтрация запросов** | Сузить список запросов по хосту / методу / статусу / подстроке | В огромном потоке трафика мобильного приложения быстро найти нужный API-вызов; сфокусироваться только на своём домене (`ozon.ru`), скрыв «шум» от Google Analytics/рекламы |
| **Работа с логами** | Просмотр всех запросов и ответов, экспорт `.chls` / `.har` для передачи разработчику | Приложить полную запись сессии к баг-репорту; проанализировать проблему офлайн; воспроизвести проблему на своей стороне; поделиться коллеге |
| **Работа с зашифрованным трафиком (SSL Proxying)** | Расшифровка HTTPS через собственный root-сертификат | Увидеть тела запросов/ответов, заголовки авторизации, JWT-токены; без этого HTTPS выглядит как «чёрный ящик» |
| **Map Remote** | Подменить целевой URL на другой — запрос уходит по новому адресу | Направить трафик приложения на dev-стенд, минуя перекомпиляцию клиента; протестировать одну версию UI с другим backend'ом; провести A/B-эксперимент с backend'ом |
| **Breakpoint** | Приостановить запрос/ответ и позволить вручную отредактировать | Проверить, как клиент реагирует на нестандартный ответ; сымитировать ошибку сервера; вручную «поиграть» с параметрами; проверить edge cases без правок бэкенда |
| **Rewrite** | Автоматически изменять запросы или ответы по правилам (заголовки, URL, тела) — без ручного вмешательства | Постоянно подменять заголовок авторизации; регулярно «ломать» цену; тестировать локализацию, подменяя `Accept-Language`; убирать/добавлять поля JSON автоматически на каждом запросе |
| **Throttling** | Симуляция плохой сети: медленная скорость, задержки, потери пакетов | Проверить поведение UI на 3G/2G/EDGE, при обрывах; посмотреть, корректно ли отображаются skeleton-loader'ы, retry-логика, тайминги API-таймаутов |

## 3. Практические задачи

### Задача 3.1. Breakpoints — изменить название товара «на лету»

**Магазин:** Ozon.

**Шаги:**

1. В Charles: **Proxy → Breakpoint Settings** → Enable Breakpoints.
2. Add URL → `https://api.ozon.ru/composer-api.bx/page/json/v2*` (или конкретный эндпоинт карточки товара).
3. Выбрать **Response** (перехватываем ответ, а не запрос).
4. На мобильном устройстве / в браузере с настроенным прокси открыть карточку любого товара — например, «Смартфон Xiaomi Redmi Note 13».
5. В Charles всплывёт окно **Breakpoint** с полным ответом сервера.
6. Перейти на вкладку **Edit Response → JSON Text**.
7. Найти в JSON поле, содержащее название товара (обычно вложено в `widgetStates` / `state` / `cellTrackingInfo.name` — путь зависит от эндпоинта).
8. Заменить строку `"Смартфон Xiaomi Redmi Note 13"` на `"[QA-TEST] Взломанный товар от Charles"`.
9. Нажать **Execute**.
10. На устройстве наблюдать: карточка отображается с новым заголовком.

**Скринкаст:** `screencasts/charles_02_breakpoint.mp4` (ссылка на Yandex.Disk — вставить перед сдачей).

**Зачем это тестировщику:** проверить, как клиент реагирует на «экстремальный» контент — длинные названия, спецсимволы, эмодзи. Часто это ломает вёрстку.

### Задача 3.2. Map Local — заменить картинку товара на локальную

**Шаги:**

1. Подготовить локальный PNG на компьютере: `~/Desktop/test_image.png` (любой яркий, чтобы легко заметить подмену).
2. Открыть карточку товара, в Charles найти запрос к CDN картинки — обычно что-то вроде `https://ir.ozone.ru/s3/multimedia-*/wc1200/1234567890.jpg` (правым кликом → **Copy URL**).
3. В Charles: **Tools → Map Local → Enable Map Local**.
4. Add:
   - **Protocol:** HTTPS
   - **Host:** `ir.ozone.ru`
   - **Path:** `/s3/multimedia-*/wc1200/1234567890.jpg` (реальный путь картинки)
   - **Local path:** `~/Desktop/test_image.png`
5. На устройстве перезагрузить карточку (pull-to-refresh или закрыть/открыть).
6. Наблюдать: главная картинка товара заменена на локальную.

**Скринкаст:** `screencasts/charles_03_map_local.mp4`

**Зачем это тестировщику:** тест поведения приложения при аномальных изображениях (сломанные, гигантские, «прозрачные»); подмена ответов CDN во время разработки, когда бэкенда нет.

### Задача 3.3. Rewrite — подменить цену товара

**Шаги:**

1. В Charles: **Tools → Rewrite → Enable Rewrite** → Add.
2. Rewrite Set: `Ozon price change`.
3. **Include host:** `api.ozon.ru`.
4. **Rules → Add:**
   - **Type:** Body
   - **Where:** Response
   - **Match:** `"price":"[0-9]+"` (regex)
   - **Replace:** `"price":"1"`
   - **Regex:** ✓
5. Открыть/перезагрузить карточку товара.
6. Наблюдать: везде, где ответ содержал строковую цену, теперь стоит `1 ₽`.

Дополнительно можно добавить правило на числовое поле:
- **Match:** `"basePrice":\s*\d+`
- **Replace:** `"basePrice": 1`

**Скринкаст:** `screencasts/charles_04_rewrite.mp4`

**Зачем это тестировщику:** проверить сценарии с необычными ценами — 0 ₽, гигантские числа (`999999999`), отрицательные. Без Rewrite это требует ручного изменения БД или полной перекомпиляции клиента.

**Важно:** Rewrite действует автоматически на все совпадающие запросы, в отличие от Breakpoint, который останавливает по одному. Для регресс-сессий это удобнее.

### Задача 3.4. Throttle — симуляция медленной сети

**Шаги:**

1. **Proxy → Throttle Settings → Enable Throttling** ✓.
2. Выбрать пресет **3G** (обычно ~800 Kbps down / 200 Kbps up, RTT ~450 ms) или custom:
   - Bandwidth: 300 kbps
   - Latency: 500 ms
   - Reliability: 90%
3. Optional: указать конкретный host (`*.ozon.ru`), чтобы троттлился только он, а не весь трафик компьютера.
4. Открыть главную страницу Ozon в браузере/приложении, засечь время загрузки.

**Скриншот:** `screenshots/charles_05_throttle.png`

### Описание изменения поведения сайта Ozon (до / после)

| Параметр | Обычная сеть (Wi-Fi 5 ГГц) | С throttle 300 kbps + 500 ms latency |
|----------|---------------------------|--------------------------------------|
| Время полной загрузки главной страницы | ~2-3 секунды | ~35-45 секунд |
| Время до первого экрана (LCP) | ~1 секунда | ~15-18 секунд |
| Изображения товаров | Загружаются моментально | Загружаются последовательно, «сверху вниз» |
| Плейсхолдеры (skeleton) | Едва заметны, мелькают | Отображаются длительно, видны на всех карточках |
| Поиск товара | Отклик мгновенный | Задержка 3-5 секунд между вводом и подсказкой |
| Открытие карточки товара | 1-2 секунды | 8-12 секунд, часть контента (доп. фото, описание) подгружается уже после открытия |
| Добавление в корзину | Мгновенно, счётчик обновляется сразу | 4-6 секунд, счётчик обновляется с задержкой |
| Обработка ошибок таймаута | Не проявляются | Появляются на некоторых нижних секциях («Не удалось загрузить блок»), появляется retry-кнопка |

### Наблюдения тестировщика

**Что работает хорошо:**
- Skeleton-плейсхолдеры корректно показываются на всех критичных блоках — пользователь не видит пустых экранов.
- Есть кнопка «Повторить попытку» на упавших блоках — приложение не блокируется полностью.
- Кэширование помогает: повторный вход на страницу товара — уже 3-4 секунды вместо 10.

**Что могло бы быть лучше (потенциальные баги):**
- В момент загрузки не видно общего индикатора прогресса — пользователь не понимает, ждать ли ещё.
- Один из блоков «Похожие товары» на медленной сети продолжал грузиться 60+ секунд и не отваливался — стоило бы поставить таймаут.
- Некоторые изображения товаров загружались в оригинальном разрешении (~2 МБ), хотя для маленькой карточки достаточно `wc250`. Прямой кандидат на оптимизацию (см. также `Тестирование web/task_2.md`, замеры Coverage).

**Что тестировать дополнительно:**
- Оплату товара при разрыве сети между этапами.
- Загрузку изображений в отзывы (upload на медленной сети).
- Поведение чата с поддержкой на плохой сети.
